# Lingvoteka

Личная платформа для материалов уроков итальянского: загрузка, проверяемое AI-извлечение слов и тем, интервальное повторение, теория и упражнения. Интерфейс на русском, задания на итальянском. Код разделён на React-клиент (`apps/web`) и NestJS API (`apps/api`); данные принадлежат пользователю, а состояние повторения хранится отдельно для каждого аккаунта. Клиент использует TanStack Query для серверных списков и фонового обновления статусов; кэш создаётся отдельно для каждой авторизованной сессии.

Текущие этапы, критерии проверки и будущий Telegram Mini App описаны в [плане](docs/roadmap.md).

## Запуск локально

Нужны Node.js 22+, pnpm 11 и PostgreSQL. Создай базу `lingvoteka` и выполни:

```sh
pnpm install
cp .env.example apps/api/.env
# Отредактируй apps/api/.env: DATABASE_URL и BETTER_AUTH_SECRET обязательны.
pnpm db:migrate
pnpm dev
```

Если pnpm блокирует установочные скрипты Prisma или esbuild, выполни `pnpm approve-builds`, разреши их и повтори `pnpm install` и `pnpm db:migrate`.

Фронтенд откроется на `http://localhost:5173`, API — на `http://localhost:3001/api`, документация API — на `http://localhost:3001/api/docs` (JSON: `/api/openapi.json`). Vite проксирует `/api`, поэтому браузер работает с одним origin. `pnpm dev` запускает также отдельный worker: API ставит в очередь pg-boss разбор материалов и генерацию теории с упражнениями. Worker также определяет категории новых слов, добавленных вручную. Очереди живут в PostgreSQL; закрытие страницы или перезапуск API не теряет задания. Для production запусти API (`pnpm --filter @lingvoteka/api start`) и worker (`pnpm --filter @lingvoteka/worker start`) как отдельные процессы. Им нужны одна постоянная PostgreSQL и доступ к одному закрытому S3-совместимому бакету.

Локально файлы по умолчанию хранятся в `UPLOAD_DIR`. Для S3 укажи `FILE_STORAGE=s3`, `S3_BUCKET` и `S3_REGION`; для другого S3-совместимого сервиса добавь `S3_ENDPOINT`. Пару `S3_ACCESS_KEY_ID`/`S3_SECRET_ACCESS_KEY` указывай вместе либо используй стандартный источник учётных данных AWS SDK (например, IAM role). API и worker должны получать одинаковые настройки. В production S3 обязателен, а сторонний endpoint должен использовать HTTPS. Railway Bucket использует виртуальный адрес бакета, поэтому для него нужно `S3_FORCE_PATH_STYLE=false`; старые S3-совместимые сервисы с адресом-путём могут оставить `true`. Бакет должен быть закрытым: публичный доступ отключён, приложению нужны только права на запись, чтение и удаление объектов в своём префиксе `materials/`. Клиент скачивает файл через API после проверки владельца; прямых публичных ссылок нет. Для переноса уже сохранённых файлов после копирования базы используется команда `pnpm --filter @lingvoteka/api migrate:files:s3 -- --apply`: она загружает файлы в бакет и меняет их ключи в выбранной базе, не удаляя локальные оригиналы. Без `--apply` команда только проверяет исходные файлы.

`BETTER_AUTH_SECRET` должен содержать не менее 32 случайных символов. Регистрация и вход работают без подтверждения почты и без проверочного письма. Пока домен для отправки не настроен, `EMAIL_PROVIDER=disabled` по умолчанию локально и в production: письма не отправляются, восстановление пароля скрыто и его API-маршрут возвращает 503. Адрес нужен только для входа; важно сохранить пароль. Если позже понадобится локально включить SMTP, задай `EMAIL_PROVIDER=smtp`, `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASSWORD` и `SMTP_FROM` в `apps/api/.env`, затем перезапусти API. Если SMTP временно недоступен, в режиме разработки ссылка сброса пароля появится в терминале API; сбой SMTP не останавливает API. `EMAIL_REPLY_TO` задаёт адрес для ответов. Для production также нужен `REGISTRATION_INVITE_CODE`; поле кода показано при регистрации. Не публикуй `.env` и не используй пример секрета из `.env.example`.

Для разбора материалов, генерации теории и упражнений задай `GEMINI_API_KEY`. AI-вызовы идут через серверный адаптер провайдера; сейчас реализован `AI_PROVIDER=gemini` (значение по умолчанию). Модель настраивается через `GEMINI_MODEL` (по умолчанию `gemini-3.5-flash-lite`). Без ключа материалы и записи можно добавлять вручную; AI-действия покажут явную ошибку. Ключ остаётся только на сервере. При использовании AI текст и файлы уроков передаются в Gemini.

## Публичное размещение

Сайт: [lingvoteka.vercel.app](https://lingvoteka.vercel.app). Статус фронтенда и логи сборки: [Vercel](https://vercel.com/daria-s-projects6/lingvoteka/deployments). Состояние API, worker, PostgreSQL и Bucket: [Railway](https://railway.com/project/0b87569c-2afb-49a3-a6ea-d96706e9d753).

Фронтенд размещается в Vercel из `apps/web`: production-ветка `dev`, framework Vite. Файл `apps/web/vercel.json` проксирует `/api/*` на публичный Railway API и направляет остальные маршруты в React-приложение. При смене домена API обновите этот адрес в `vercel.json`. Это сохраняет cookie-сессии на одном домене с фронтендом; локально продолжает работать Vite-прокси.

В Railway нужны PostgreSQL, закрытый Bucket и две службы из того же репозитория/ветки `dev`. Обе собираются из корневого `Dockerfile`. У API команда запуска `pnpm --filter @lingvoteka/api start`, healthcheck `/api/health`, а перед запуском — `pnpm --filter @lingvoteka/api exec prisma migrate deploy`. У worker команда `pnpm --filter @lingvoteka/api start:worker`; публичный домен ему не нужен. Обе службы получают `DATABASE_URL` ссылкой на PostgreSQL и одинаковые `FILE_STORAGE=s3`, `S3_BUCKET`, `S3_REGION`, `S3_ENDPOINT`, `S3_FORCE_PATH_STYLE=false`, `S3_ACCESS_KEY_ID`, `S3_SECRET_ACCESS_KEY` ссылками на Bucket. API дополнительно получает `BETTER_AUTH_SECRET`, `BETTER_AUTH_URL` и `WEB_ORIGIN` (оба URL — публичный адрес Vercel), `REGISTRATION_INVITE_CODE`, `AI_PROVIDER`, `GEMINI_API_KEY`, `GEMINI_MODEL` и `NODE_ENV=production`; worker нужны `NODE_ENV`, `AI_PROVIDER`, `GEMINI_API_KEY`, `GEMINI_MODEL`. Секреты хранятся только в настройках Railway, не в Git и не во фронтенде.

Для возврата к восстановлению пароля после покупки домена: подтвердить его в Resend, задать для службы API `EMAIL_PROVIDER=resend`, `RESEND_API_KEY`, `RESEND_FROM` с адресом на подтверждённом домене и нужный `EMAIL_REPLY_TO`, затем проверить доставку настоящего письма. Тестовый `onboarding@resend.dev` работает только для адреса аккаунта Resend и не подходит для публичного восстановления. Локальные настройки SMTP сохраняются: режим выбирает `EMAIL_PROVIDER`.

Автодеплой требует GitHub-интеграции обеих платформ: Vercel должен отслеживать `dev` как production branch, а обе службы Railway — репозиторий и trigger branch `dev` с включённым Auto Deploy. Аккаунт Railway должен быть связан с GitHub, а Railway GitHub App — иметь доступ к этому репозиторию. Нельзя ограничивать Railway watch paths только частью репозитория, если каждый коммит должен запускать оба деплоя. В Railway на тарифах Free, Trial и Hobby исходящий SMTP закрыт; с Яндекс SMTP нужен Pro или переход на почтовый HTTPS API.

## Основной сценарий

1. Добавь материал: текст и/или до пяти файлов. Поддерживаются TXT, DOCX, PPTX, PDF, JPG и PNG; один файл до 10 МБ, суммарно до 20 МБ. Название подставляется из имени первого файла без расширения, его можно изменить. Google-тест и онлайн-доску можно экспортировать в PDF, сохранить скриншотом или скопировать как текст.
2. AI предложит слова и грамматические темы в фоновом задании. Можно закрыть страницу и вернуться к результату. Проверка обязательна: исправь, удали или добавь записи перед сохранением. Если AI недоступен, тот же экран позволяет заполнить их вручную.
3. Новые слова появляются в словаре и очереди повторения. AI предлагает для каждого слова часть речи и лексическую тему (например, «Существительное» и «Спорт»); обе категории можно поправить при проверке материала. В словаре можно группировать слова по любой из этих осей, выбрать группу и искать слово. Для ранее сохранённых слов обработка начинается только после нажатия кнопки «Определить темы для слов без категории»; слова и переводы при этом передаются Gemini. У каждого нового слова создаётся отдельная карточка «итальянский → русский»; состояние и история FSRS привязаны к карточке, что позволит позже добавить другие направления с собственным расписанием. Нажми на карточку, чтобы перевернуть её; после просмотра перевода смахни влево («не помню») или вправо («помню») либо выбери одну из четырёх оценок. За день вводится до 10 новых карточек. Просроченные карточки идут первыми.
4. В грамматике открой тему и создай краткую теорию с упражнениями. Генерация выполняется в фоне; можно закрыть страницу и вернуться позже. AI-объяснение явно помечено. Ответ проверяется на сервере, после чего показываются правильный вариант и пояснение.

Исходные файлы скачиваются только через защищённый маршрут владельца. PDF и изображения читаются моделью визуально. Из DOCX и PPTX извлекается текст и встроенные JPG/PNG; если изображений слишком много или они слишком велики, приложение предложит экспортировать документ в PDF. Произвольные ссылки на Google-тесты не импортируются. AI-ответы могут быть ошибочными, поэтому требуется ручная проверка извлечения и явная пометка теории.

## Telegram Mini App: первая часть этапа 6

Реализована основа: проверка подписанного `initData` на сервере (срок 10 минут), явная привязка после обычного входа, последующий вход в тот же аккаунт по Telegram, адаптация темы/отступов и BackButton. Новый пользователь пока регистрируется обычной формой; production-код приглашения сохраняется. Привязка хранится в отдельной таблице `TelegramIdentity`; совпадение имени или почты ничего не объединяет. Таблицы интеграции добавлены аддитивными миграциями. Для обычного браузера Telegram SDK не загружается. Без `TELEGRAM_BOT_TOKEN` Telegram-вход недоступен, обычный вход продолжает работать.

Бот принимает фразы, текст, фотографии и документы в личном чате после привязки аккаунта. Поддерживаются те же форматы и ограничения, что на сайте: до 5 файлов на материал, каждый до 10 МБ, вместе до 20 МБ. Альбом собирается в один материал после 4 секунд без новых частей. Поздние части после начала обработки не теряются молча: бот просит отправить их отдельно. Название берётся из первого файла или первой строки текста. Повторная доставка update/message не создаёт второй материал. Слова появляются в словаре только после ручного подтверждения черновика.

Приём, скачивание и ответы Telegram выполняет постоянная очередь pg-boss в процессе API; существующий worker выполняет тот же AI-разбор. Токен нужен только API, worker его не получает. Полученный текст/дескрипторы файлов временно хранятся до импорта и очищаются из inbox после переноса в материал. Квитанции команд без содержания сохраняются 30 дней. После готовности бот обновляет сообщение кнопкой «Проверить слова и темы» и объясняет подтверждение в приложении; повторные попытки доставки ответов могут дать повтор сообщения, но не материала. `/start` открывает меню «Добавить материал», «Повторить слова», «Мои материалы», «Как это работает»; `/add` и `/help` показывают подсказки прямо в чате. Меню не запускает AI и не создаёт материалы. Webhook принимает `message` и `callback_query`; каждый клик имеет отдельную постоянную квитанцию. Есть также команды `/cards` и `/materials`. Профиль и аватар из `assets/telegram` применяются автоматически; хеш аватара сохраняется отдельно, чтобы не загружать его при каждом перезапуске. Живой импорт текста до открытия результата подтверждён пользователем; полный путь в WebView и навигация требуют отдельной приёмки. Монетизация и PostHog сейчас не подключены.

1. Создай бота в официальном [@BotFather](https://t.me/BotFather), командой `/newbot`. Сохрани его токен только в `apps/api/.env` как `TELEGRAM_BOT_TOKEN`; в production — в настройках службы API Railway. Не добавляй токен во фронтенд или Git.
2. Задай `TELEGRAM_MINI_APP_URL=https://lingvoteka.vercel.app` или используй существующий `WEB_ORIGIN`. При наличии токена production API после запуска автоматически проверяет `getMe`, задаёт команды, меню и защищённый webhook, затем проверяет сохранённые настройки. В локальной разработке автоподключение выключено. Можно задать отдельный случайный `TELEGRAM_WEBHOOK_SECRET` (32–256 букв/цифр/`_`/`-`); по умолчанию он безопасно выводится через HMAC-SHA256 из токена с отдельным назначением `lingvoteka:telegram:webhook:v1`, одинаково на всех репликах. Токен и webhook-secret не печатаются. Успех отмечается в логе API как `Telegram setup ready` с публичным username бота; ошибка настройки не отключает обычный сайт.
3. Примени миграции `20261025050000_telegram_identity` и `20261025053000_telegram_intake` в выбранном окружении и опубликуй API/фронтенд до настройки production-webhook. Локально `pnpm --filter @lingvoteka/api exec prisma migrate deploy`, затем `pnpm dev`. Не запускай локальные smoke-тесты с production-базой.
4. `pnpm --filter @lingvoteka/api telegram:setup` проверит бота через `getMe` и покажет только публичные адреса, не меняя настройки. `pnpm --filter @lingvoteka/api telegram:setup -- --apply` установит команды, кнопку меню и webhook `/api/telegram/webhook` на том же HTTPS-домене. Не направляй production-бота на localhost. При необходимости отдельно включи Main Mini App в настройках BotFather с тем же URL.
5. Открой бота, нажми Start и кнопку приложения. В первый раз войди в существующий аккаунт Lingvoteka и нажми «Связать этот аккаунт». При следующем запуске вход выполняется по Telegram. Конфликт с уже связанной учётной записью не заменяет привязку автоматически.

Проверки: `pnpm --filter @lingvoteka/api test:telegram` — подпись/срок, подмена данных и защита webhook без внешних вызовов; `pnpm --filter @lingvoteka/api test:telegram-auth` — синтетические локальные аккаунты, конфликты привязки, cookie-вход и сохранность существующих данных с последующей очисткой. Второй тест специально отклоняет нелокальный `DATABASE_URL`. `test:telegram-intake` проверяет импорт, альбомы, гонки, восстановление и аватар в отдельной временной схеме локальной базы и с подменёнными Telegram/Gemini; схема и тестовые файлы удаляются. Секреты из hosting не нужны.

## Проверки

```sh
pnpm typecheck
pnpm build
```

Для ручной сквозной проверки при запущенных API и worker выполни `pnpm --filter @lingvoteka/api test:flow`. Проверка создаёт два временных аккаунта, анализирует синтетический текст через Gemini, проходит карточку и упражнение, проверяет изоляцию данных и удаляет тестовые аккаунты после завершения.

Для отдельной проверки распознавания скриншота выполни `pnpm --filter @lingvoteka/api test:image-flow`. Тест загружает синтетический JPG с итальянским текстом, ждёт AI-черновик и проверяет, что модель нашла напечатанные слова и грамматическую тему. Тестовый аккаунт и загруженный файл удаляются после проверки.

`pnpm --filter @lingvoteka/api test:pdf-flow` аналогично проверяет синтетический PDF через API, worker и настоящую модель. Для обоих сквозных тестов должны работать API, worker, PostgreSQL и `GEMINI_API_KEY`.

`pnpm --filter @lingvoteka/api test:office-flow` загружает синтетические DOCX и PPTX со встроенными изображениями, дожидается AI-черновика и проверяет извлечённые слова и фрагменты источника. `pnpm --filter @lingvoteka/api test:recovery-flow` воспроизводит состояние ошибки AI на синтетическом материале, проверяет ручное сохранение и затем настоящий повторный разбор через worker и Gemini. Обе проверки удаляют временные аккаунты и файлы после завершения.

Проверка `pnpm --filter @lingvoteka/api test:formats` локально собирает PDF, DOCX и PPTX и проверяет, что текст слайдов и документов, встроенные изображения и исходные байты PDF передаются адаптеру AI. Внешний AI в этом тесте подменён; он проверяет подготовку файлов, а не качество распознавания моделью.

Схема базы и миграции — в `apps/api/prisma`. Настройки темы сохраняются в аккаунте и локальном браузере. Внизу страниц листья декоративной лозы плавно покачиваются с помощью GSAP; во время загрузки данных и при `prefers-reduced-motion` движение не показывается.

Основа FSRS: [ts-fsrs](https://github.com/open-spaced-repetition/ts-fsrs). Ввод PDF/изображений и JSON-ответов: [документация Gemini](https://ai.google.dev/gemini-api/docs/document-processing), [структурированные ответы](https://ai.google.dev/gemini-api/docs/structured-output).
