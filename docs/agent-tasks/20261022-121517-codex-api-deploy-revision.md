## Цель и уточнения пользователя

На этапе 5 подтвердить, что автодеплой Railway действительно обновил API после push, а не только что старый `/api/health` отвечает. Почта и бэкапы отложены; Telegram Mini App не начинать без согласования.

## Решения и результат

Официальная документация Railway описывает runtime-переменную `RAILWAY_GIT_COMMIT_SHA` для GitHub-деплоев. Добавлено публичное поле `revision` в `/api/health`, равное этому SHA или `null` вне GitHub-деплоя. Поле `status` сохранено; секреты не раскрываются. Worker без публичного URL проверять отдельно по Railway, когда доступна авторизованная панель.

## Проверки

До правки `/api/health` отвечал HTTP 200, но не содержал ревизию. После правки `pnpm typecheck`, `pnpm build`, Prettier и `git diff --check` прошли. Коммит `835752b` отправлен в `origin/dev`; Vercel сообщил success. Публичный `/api/health` в 12:20+08 по-прежнему ответил только `{"status":"ok"}`, то есть новая версия API не подтверждена. Сохранённый вход Railway CLI недействителен; скрытая вкладка Railway также без авторизации.

Официальный [статус Railway](https://status.railway.com/) 22 октября сообщает, что сборки для Trial ещё приостановлены; Railway аннулировал API-токены. [Руководство Railway](https://blog.railway.com/p/security-disclosure-recommendation-redeploy-buckets-and-reconnect-github-after-the-credential-reset) сообщает о сбросе S3-ключей бакетов и GitHub-токенов и требует переподключения GitHub и повторного деплоя сервисов, использующих бакет. Пользователь 22 октября ответила «готово» на просьбу переподключить GitHub и проверить ветку `dev` у API/worker. Публичный `/api/health` в 12:28+08 по-прежнему вернул только `{"status":"ok"}`; статус Railway в 04:17 UTC разрешал сборки только Enterprise. Значит новая API-ревизия пока не подтверждена, а состояние конкретных деплоев без авторизованной панели не видно.

## Следующие шаги / препятствия

После восстановления сборок Railway запустить Deploy Latest Commit у API/worker при необходимости, убедиться, что оба сервиса получили обновлённые ссылочные S3-ключи. Затем сравнить `revision` публичного API с HEAD `dev` и проверить загрузку/скачивание файла. Дополнительно по официальному уведомлению требуется ротация прочих секретов Railway и проверка журналов; не запрашивать их значения в чате. Отсутствие `revision` нельзя считать успехом.
