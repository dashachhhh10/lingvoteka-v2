## Решения и результат

В HEAD `59091de` уже есть `EMAIL_PROVIDER=disabled`, отключение маршрута восстановления и скрытие ссылки во фронтенде. Railway API реально настроен на `EMAIL_PROVIDER=disabled`; публичный `/api/capabilities` возвращает `passwordResetAvailable: false`, а запрос сброса — 503 с `PASSWORD_RESET_DISABLED`. Локальный `apps/api/.env` теперь тоже задаёт `EMAIL_PROVIDER=disabled`; после перезапуска API логирует `Email delivery disabled`. Регистрация и вход не требуют подтверждения почты.

Отправка стала явным opt-in: отсутствие `EMAIL_PROVIDER` в коде теперь не активирует SMTP, `.env.example` задаёт `disabled`; SMTP и Resend можно включить явным выбором. README и общая память уточнены, но соседние изменения в этих файлах принадлежат завершённой задаче общего контекста и не должны попадать в этот коммит целиком.
