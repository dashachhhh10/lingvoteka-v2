# План Lingvoteka

Этот план отражает текущий объём работы. К следующему этапу переходим после просмотра и согласования результата предыдущего.

| Этап | Результат | Статус |
| --- | --- | --- |
| 0. Направление | Сценарий, экраны и визуальный язык | Согласован; первоначальные макеты сохранены в `design/stage-0` |
| 1. Доступ | Регистрация, вход, восстановление доступа и изоляция аккаунтов | Регистрация и вход реализованы без подтверждения почты; восстановление пароля временно отключено до подключения домена для отправки |
| 2. Материалы | Загрузка текста и файлов, фоновый AI-разбор, проверка черновика перед сохранением | Реализован; проверяется на реальных и синтетических уроках |
| 3. Повторение | Отдельные карточки и расписания FSRS, переворот по нажатию и оценка свайпом | Реализован; входит в сквозную проверку |
| 4. Грамматика | Темы, теория и упражнения с проверкой ответа | Реализован; входит в сквозную проверку |
| 5. Проверка и запуск | Проверить весь путь, мобильный интерфейс, ошибки, хранение файлов и работу после перезапуска; подготовить запуск | В работе |
| 6. Telegram Mini App | Открывать тот же учебный сценарий внутри Telegram | После согласования этапа 5 |

## Этап 5: критерии завершения

- Проверить импорт текста, PDF, PPTX, DOCX и скриншотов, включая неудачное распознавание и повторную обработку. Реальный JPG уже проверен через Gemini; результаты AI остаются черновиком до подтверждения.
- Пройти путь «материал → проверка слов и тем → карточки → грамматика → упражнения» на настоящем уроке и проверить, что данные двух аккаунтов не смешиваются.
- Проверить светлую и тёмную темы, узкий экран, клавиатуру, жесты карточек, состояния загрузки и ошибок. Особое внимание — черновику при уходе со страницы и переключениям между разделами.
- Проверить API, worker, PostgreSQL и закрытое файловое хранилище после перезапуска. Перед публичным запуском настроить постоянные окружения, секреты, HTTPS и резервное копирование.
- Показать работающий результат и получить согласование перед этапом 6.

## Стили фронтенда

Tailwind CSS v4 уже подключён к Vite. Новые и затрагиваемые компоненты собираем из его готовых утилит для сетки, отступов, типографики, адаптивности и состояний. Цвета Lingvoteka остаются в общих токенах и доступны Tailwind-классам, поэтому светлая и тёмная темы сохраняют одну палитру. Повторяющиеся сочетания оформляем как React-компоненты; отдельный CSS оставляем для анимаций GSAP, сложной графики лозы и случаев, которые неудобно выразить утилитами. Существующие экраны переносим постепенно при их доработке, без изменения согласованного макета только ради смены способа стилизации. Подход к токенам соответствует [документации Tailwind CSS](https://tailwindcss.com/docs/theme).

## Этап 6: Telegram Mini App

1. Разместить существующий React-клиент и NestJS API по HTTPS с маршрутом `/api` на том же origin. Добавить режим запуска внутри Telegram к этому же фронтенду, сохранив веб-версию и общий REST API. В Mini App должен работать весь основной путь: загрузка, проверка разбора, словарь, карточки, грамматика и упражнения.
2. Создать бота и настроить точку входа Mini App через BotFather. Для входа передавать на сервер исходный `Telegram.WebApp.initData`, проверять подпись и свежесть данных, затем связывать Telegram ID с существующим аккаунтом Lingvoteka и выдавать серверную сессию. Привязку к уже созданному аккаунту подтверждать из его авторизованной сессии; по имени или почте из Telegram аккаунты не объединять. Данные `initDataUnsafe` не использовать как доказательство личности. Это соответствует [правилам проверки Telegram](https://core.telegram.org/bots/webapps#validating-data-received-via-the-mini-app).
3. Адаптировать оболочку под Telegram: учитывать его светлую/тёмную тему, высоту окна и safe area, BackButton и конфликт вертикальных жестов Telegram со свайпами карточек. Проверить загрузку файлов внутри WebView. Ориентир — [официальные рекомендации для Mini Apps](https://core.telegram.org/bots/webapps#designing-mini-apps).
4. Проверить полный сценарий в Telegram на iOS, Android и desktop, повторный вход, истечение сессии, ошибки сети и независимость обычной веб-версии. После этого согласовать публикацию кнопки запуска бота.

На этом этапе бот нужен как точка входа. Напоминания о дедлайнах и отправка сообщений не входят в согласованный сценарий.
